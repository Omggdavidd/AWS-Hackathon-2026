# Implementation plans

Lightweight plans for work that is too big to hold in one PR description: a multi-PR feature, a cross-cutting change, or anything that several people will work on. Not required for small changes.

- One file per plan: `docs/plans/YYYY-MM-DD-short-title.md`, from `plan-template.md`.
- A plan is a coordination tool, not a spec. Keep it to a page. Update it when reality diverges; delete or mark it done when the work merges.
- Decisions discovered while planning go into ADRs, not into the plan.
- Day-to-day progress lives in `STATUS.md`, not in the plan.

Claude Code: use plan mode to draft, then save the result here only if other people need it.

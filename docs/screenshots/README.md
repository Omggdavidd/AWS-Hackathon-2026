# Screenshots

Product shots used by `README.md` and the submission material. `scripts/screenshots.mjs` regenerates
them, so a front-end change does not leave the images describing a UI that no longer exists — which
is how they went stale twice on Sep 13.

## Regenerate

Everything renders from the seeded demo ledger: no AWS account, no Bedrock, no network.

```sh
# 1. Playwright, installed outside the repository (see below)
PW=$(mktemp -d) && npm i --prefix "$PW" playwright

# 2. A dev server on the seeded ledger; OPENLOOP_RESET=1 restores demo/seed-ledger.json first
OPENLOOP_RESET=1 pnpm --filter @openloop/web dev

# 3. In another shell, from the repository root
PLAYWRIGHT_MODULE="$PW/node_modules/playwright" node scripts/screenshots.mjs
```

Re-shoot one screen with `ONLY=dashboard-board node scripts/screenshots.mjs`, and write somewhere
harmless first with `OUT_DIR=/tmp/shots` when you only want to look.

**Playwright is not a repository dependency.** Adding it would put a browser download in front of
every `pnpm install` and every CI run, to serve a script that runs by hand a few times a release.
The script resolves it at run time from `PLAYWRIGHT_MODULE` instead. If the machine already has a
Chromium that Playwright's npm package does not recognise — a different build number — point at it
rather than downloading a second copy:

```sh
PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome
```

## What the script fixes, so shots stay comparable

Cookies are set before the first paint, so nothing catches a first-run overlay by accident:
`openloops-toured=1` (no tour), `openloops-theme` (the server reads it in `layout.tsx`), and
`openloops-agent`.

That last one is the literal string **`Your agent`**. The dashboard will not render without a name —
`app/page.tsx` returns `Welcome` when the cookie is absent — and `Your agent` is what the app already
shows wherever a name is missing, so no invented branding reaches judge-facing assets. If the team
names the agent, change that one value and re-run.

Board grouping comes from `localStorage` (`openloops:board:<user>:v1:by`), set through an init script
before load. The decision sheet opens from `?action=<id>`, so it needs no click. Animations run under
`reducedMotion: 'reduce'`.

Sizes follow what is tracked: **1440×900** desktop, **390×844** mobile. Both are asserted by eye
against the committed files — if you change a viewport here, every shot at that size changes too.

## The one file the script does not produce

`live-vercel.png` is the deployed app at its public URL, kept as evidence that it is live. Recapture
it by hand against <https://openloop-neon.vercel.app>.

Every other file in this directory is regenerated by the script and safe to overwrite.

# web

Next.js 16 product UI (ADR-0010): dashboard, loop detail, approvals, activity feed. Server components and server actions read the ledger through `@openloop/shared`; the browser never sees AWS or Google credentials.

```
pnpm --filter @openloop/web dev     # http://localhost:3000
pnpm --filter @openloop/web build
```

Data source: with `OPENLOOP_LEDGER_TABLE` set (see `.env.example`), the DynamoDB table shared with the agent; otherwise `LocalLedgerStore` on `.openloop/ledger.json` at the repo root, created from `demo/seed-ledger.json` on first run (`OPENLOOP_LEDGER_FILE` overrides the path, `OPENLOOP_RESET=1` re-seeds).

Scan: with `OPENLOOP_RUNTIME_ARN` and the table set, the **Scan inbox** button posts to `/api/scan`, which invokes the deployed AgentCore runtime and proxies its progress stream to the browser while the runtime writes loops to the table; the dashboard refreshes as they land. A full scan takes about four minutes (`maxDuration = 300` on the route). **Check for new mail** posts `?variant=delta`, which replays the next-morning batch: the deposit and the write-up resolve, the flight gains evidence, a library loop appears. AWS credentials come from `~/.aws` locally and from environment variables on Vercel.

`AGENTS.md` in this directory is generated by `next dev` and points agents at the bundled Next.js docs; keep it committed.

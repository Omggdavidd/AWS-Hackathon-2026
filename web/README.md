# web

Next.js 16 product UI (ADR-0010): dashboard, loop detail, approvals, activity feed, and a message page behind every evidence link. Server components and server actions read the ledger through `@openloop/shared`; the browser never sees AWS or Google credentials.

```
pnpm --filter @openloop/web dev     # http://localhost:3000
pnpm --filter @openloop/web build
```

Data source: with `OPENLOOP_LEDGER_TABLE` set (see `.env.example`), the DynamoDB table shared with the agent; otherwise `LocalLedgerStore` on `.openloop/ledger.json` at the repo root, created from `demo/seed-ledger.json` on first run (`OPENLOOP_LEDGER_FILE` overrides the path, `OPENLOOP_RESET=1` re-seeds).

Scan: with `OPENLOOP_RUNTIME_ARN` and the table set, the **Scan inbox** button posts to `/api/scan`, which invokes the deployed AgentCore runtime and proxies its progress stream to the browser while the runtime writes loops to the table; the dashboard refreshes as they land. A full scan takes about four minutes (`maxDuration = 300` on the route). **Check for new mail** posts `?variant=delta`, which replays the next-morning batch: the deposit and the write-up resolve, the flight gains evidence, a library loop appears. **Handle what you can** posts to `/api/handle`: the agent executes every allowed action and lists what needs the user. **Catch me up** posts to `/api/catch-up` and shows what changed since the last check, each line linking to its loop. **Approve** on a decision sheet (`/decisions?action=<id>`, reached from Review on the Decisions page, the strip above the Today list, or a loop's action card) marks the action approved and asks the agent to execute it (the button shows a pending state for the ~20 seconds it takes); without a runtime configured the record is only marked approved. Approve and Decline confirm in place: the first click arms the button for eight seconds and renames it, the second submits (`components/decision-buttons.tsx`), because an approval reaches the runtime and cannot be pulled back. The sheet (`components/decision-sheet.tsx`) shows what is being authorised as the artefact it would be, from `describeProposal` in `lib/decisions.ts`: the email with its recipient, subject and body; the payment with its amount and portal; the slots a booking would choose between; anything else as labelled fields, hiding nothing. Beneath it, the evidence line the loop rests on with a link to the original. Executed actions render what the agent produced: the draft email, the calendar event, the reminder (`components/action-effect.tsx`); cancelled and failed ones show the reason from the audit trail. The four operations live in one panel (`components/agent-panel.tsx`): the controls sit in a row beside the agent's name and when it last checked, and whatever ran last renders in a single result slot beneath them, formatted as what it is: the catch-up digest as a lead line plus items with state chips and loop links, handled actions as done and needs-you lists, a scan as a progress bar and a live log. Screenshots: `docs/screenshots/`. AWS credentials come from `~/.aws` locally and from environment variables on Vercel.

Loop page (#67): one responsibility in the order a person checks it. The header carries the state chip, the title and a facts strip (when, area, amount, who, any reminder, confidence). *What to do* comes first: the next action as the lead sentence, the consequence labelled "If ignored", and the buttons: "I already did this" resolves the loop and cancels what it would have left behind, while "Remind me tomorrow" and "Ignore" park it in Watching so it stops being counted in "N things need you" (`lib/park.ts`, #36). Remind sets `remindAt` a day out and shows it in the facts strip; Ignore clears it. Neither calls the agent, and neither touches proposed actions: parking says "not now", not "done". Ignore is hidden on a loop already in Watching, where it would do nothing. *What I found* lists each piece of evidence as a quote with a quiet meta line (what it did to the loop, the date, a link to the source, how sure the agent is); the left rule takes the state color of what the evidence did. *What the agent did* lists actions as cards with the artifact inside (`components/action-effect.tsx`): draft email, calendar event, reminder; proposed ones carry Approve and Decline. *History* folds any reason longer than a sentence behind a native disclosure so the agent's full rationale is one click away without dominating the page. The overview hero carries a live clock in the demo time zone (`components/live-clock.tsx`, rendered empty on the server and filled after mount).

Change banner (#39): in the Today pane before a loop is chosen (and in the notification centre), one or two sentences of what changed in the last 24 hours, built in `lib/changes.ts` from the audit trail and the loops' current states rather than by parsing reasons — an event says a loop changed, the loop says what it became. Only `state_changed`, `loop_created` and `action_executed` count: evidence and scans are the agent working, not a change in the world (SPEC §8H, never "you have 6 emails"). Up to two loops are named and linked, then "and N more". Nothing notable in the window means no banner at all, so a cold seeded ledger shows none and one appears after a delta run. Dismissal stores the newest counted event's timestamp in the `openloops-seen` cookie, read by the server so there is no flash, and the banner returns when something newer happens instead of staying hidden forever.

Deployment (#19): Vercel project `openloop` under David's account, root directory `web`, Node 22, framework Next.js, connected to the GitHub repository so `main` deploys to production and every PR gets a preview. Production URL https://openloop-neon.vercel.app. Environment variables (production and preview): `OPENLOOP_LEDGER_TABLE`, `OPENLOOP_RUNTIME_ARN`, `AWS_REGION`, and the access key of the IAM user `openloop-web`, whose only policy (`OpenLoopWebLeastPrivilege`) allows item and query actions on `openloop-ledger` and `bedrock-agentcore:InvokeAgentRuntime` on the OpenLoop runtime. The key exists only in Vercel. Routes declare `maxDuration` 300 for scan and handle, which the plan accepted at build time; a delta scan and a catch-up were exercised through the public URL, a full four-minute scan was not.

Sources: `/messages/[id]` renders one demo email or calendar event so every evidence line and source ref on a loop page links back to what the agent actually read (SPEC §12). The inbox comes from `demo/seed-inbox.json` merged with `seed-inbox-delta.json`, bundled at build time rather than read from disk; unknown ids 404.

Shell and views (#88, #105): every destination is a route in the rail on the left (`components/app-rail.tsx`; bottom tabs on phones): **Today** (`/`), **Board** (`/board`), **Calendar** (`/calendar`), **Decisions** (`/decisions`, every proposed action the agent will not take without you, from `lib/decisions.ts`), **Activity** and **About**. The top bar carries the agent and when it last checked, the bell and the theme toggle. State counts live in the headline and on the rows, not in the navigation. The old `/?view=board` and `/?view=calendar` links redirect. **Today** is a split view on screens 1100px and wider: the list on the left and the chosen loop on the right (`/?loop=<id>`), rendered by `components/loop-detail.tsx`, the same server component `/loops/[id]` uses, so every action works in both places; with nothing chosen the pane shows the share closed, what waits on a decision and what changed since the last look. Below 1100px the same URL opens the loop as a sheet over the list. The list follows what Things, Todoist and Asana converged on: rows grouped by time (Overdue, Today, This week, Later, No date, Earlier for past dates the user does not owe, Resolved at the bottom), each row in fixed columns (#106): the area of life as a glyph (`AreaIcon`, #91), the title clamped to two lines with who it is from and the verb and amount beneath, the due date in words, and the state chip, which gives way to Open and Source on hover. Overdue and due-today rows carry a stripe in the state colour. Nothing on a row closes or approves anything; Done, Remind and Ignore live in the pane. Arrow keys or J and K move between rows and the pane follows the focused row after a short rest, Enter opens (`components/list-keys.tsx`). The grouping lives in `lib/format.ts` (`groupByTime`, `daysUntil`) and counts days in the demo zone, so buckets and labels flip together at local midnight. **Calendar** (`components/calendar-view.tsx`) is a six-week table from the start of this week with each loop on its due day in its state color, plus Later and No date lists beneath. **Board** (`components/loop-board.tsx`, #83, #90) is the whiteboard: a hub carrying the headline and draggable groups on connectors, grouped by state (the default) or, from one Group by menu with a line per option, by the loop's category (payments, subscriptions, forms, replies, appointments, meetings, travel, purchases, admin, other) or by its area of life (school, work, money, health, home, travel, clubs, other, #91), in which case each card carries its state icon. A group's bottom edge drags to make it taller until everything shows; arrow keys on the handle do the same. Pan and zoom have a drag threshold and gentle wheel zoom. Positions, heights and the grouping are saved per user in browser storage under `openloops:board:<userId>:v1` and validated on read; Reset restores the defaults. The headline (what needs you) and the agent panel sit above Today and Calendar; on the Board the agent panel is docked at the bottom of the canvas. Screenshots in [`docs/screenshots/`](../docs/screenshots/) predate #105 and are recaptured once the revamp (`docs/plans/2026-09-13-front-end-revamp.md`) lands.

Theme: the site defaults to light regardless of the device setting. The header toggle is available on every page and stores the choice in the `openloops-theme` cookie for one year; the root layout reads it so reloads render in the chosen theme immediately. Ledger access stays server-side; the board, navigation, theme toggle and agent controls run their interactions in Client Components.

Design references: [Linear’s March 2026 interface refresh](https://linear.app/changelog/2026-03-12-ui-refresh) informed navigation hierarchy and consistency; [web.dev animation performance guidance](https://web.dev/articles/animations-guide) informed restrained CSS transitions. These are implementation references, not additional architecture decisions.

`AGENTS.md` in this directory is generated by `next dev` and points agents at the bundled Next.js docs; keep it committed.

# web

Next.js 16 product UI (ADR-0010): dashboard, loop detail, approvals, activity feed, and a message page behind every evidence link. Server components and server actions read the ledger through `@openloop/shared`; the browser never sees AWS or Google credentials.

```
pnpm --filter @openloop/web dev     # http://localhost:3000
pnpm --filter @openloop/web build
```

Data source: with `OPENLOOP_LEDGER_TABLE` set (see `.env.example`), the DynamoDB table shared with the agent; otherwise `LocalLedgerStore` on `.openloop/ledger.json` at the repo root, created from `demo/seed-ledger.json` on first run (`OPENLOOP_LEDGER_FILE` overrides the path, `OPENLOOP_RESET=1` re-seeds).

Scan: with `OPENLOOP_RUNTIME_ARN` and the table set, the **Scan inbox** button posts to `/api/scan`, which invokes the deployed AgentCore runtime and proxies its progress stream to the browser while the runtime writes loops to the table; the dashboard refreshes as they land. A full scan takes about four minutes (`maxDuration = 300` on the route). **Check for new mail** posts `?variant=delta`, which replays the next-morning batch: the deposit and the write-up resolve, the flight gains evidence, a library loop appears. **Handle what you can** posts to `/api/handle`: the agent executes every allowed action and lists what needs the user. **Catch me up** posts to `/api/catch-up` and shows what changed since the last check, each line linking to its loop. **Approve** on a loop page marks the action approved and asks the agent to execute it (the button shows a pending state for the ~20 seconds it takes); without a runtime configured the record is only marked approved. Executed actions render what the agent produced: the draft email, the calendar event, the reminder (`components/action-effect.tsx`); cancelled and failed ones show the reason from the audit trail. Screenshots: `docs/screenshots/`. AWS credentials come from `~/.aws` locally and from environment variables on Vercel.

Loop page (#67): one responsibility in the order a person checks it. The header carries the state chip, the title and a facts strip (when, amount, who, confidence). *What to do* comes first: the next action as the lead sentence, the consequence labelled "If ignored", and the "I already did this" button. *What I found* lists each piece of evidence as a quote with a quiet meta line (what it did to the loop, the date, a link to the source, how sure the agent is); the left rule takes the state color of what the evidence did. *What the agent did* lists actions as cards with the artifact inside (`components/action-effect.tsx`): draft email, calendar event, reminder; proposed ones carry Approve and Decline. *History* folds any reason longer than a sentence behind a native disclosure so the agent's full rationale is one click away without dominating the page. The overview hero carries a live clock in the demo time zone (`components/live-clock.tsx`, rendered empty on the server and filled after mount).

Sources: `/messages/[id]` renders one demo email or calendar event so every evidence line and source ref on a loop page links back to what the agent actually read (SPEC §12). The inbox comes from `demo/seed-inbox.json` merged with `seed-inbox-delta.json`, bundled at build time rather than read from disk; unknown ids 404.

Dashboard design (#18, #52, #61): one summary sentence links to what needs you, what is waiting and what is on your radar (SPEC §7). Compact rows give the full responsibility title room to wrap, put its requester or waiting party underneath, and align the due date and amount or action on the right. Overdue, today and tomorrow deadlines use the attention color only when the user owes a move; closed loops carry no urgency dot. Recent activity shows the latest meaningful event per responsibility, with the full history on Activity. The agent's reasoning and next-action prose live in bordered sections on the loop page. The palette is a white canvas with navy text, a navy dark theme (persistent toggle, cookie-backed, circular reveal from the button through the View Transitions API with reduced-motion and unsupported-browser fallbacks), the Teal brand, and one hue per state carried by a highlighter stroke behind each state heading: pink Needs you, amber Waiting, blue Watching, green Resolved. Resolved stays a disclosure and opens on first load. The open-ring-and-dot mark has matching geometry in the wordmark, favicon and compact closed-share indicator (`components/loop-mark.tsx`, SVG with a single CSS draw-in that reduced-motion disables). Type is Inter with optical sizing, a 16px base, tabular figures, and a 68-character measure on source pages. Empty sections remain valid navigation destinations, and a Resolved shortcut opens its section. Desktop and 400px captures, light and dark, are in [`docs/screenshots/`](../docs/screenshots/).

Theme: the site defaults to light regardless of the device setting. The header toggle is available on every page and stores the choice in the `openloops-theme` cookie for one year; the root layout reads it so reloads render in the chosen theme immediately. The dashboard and ledger stay in Server Components; navigation, the theme toggle and agent buttons add client behavior.

Design references: [Linear’s March 2026 interface refresh](https://linear.app/changelog/2026-03-12-ui-refresh) informed navigation hierarchy and consistency; [web.dev animation performance guidance](https://web.dev/articles/animations-guide) informed restrained CSS transitions. These are implementation references, not additional architecture decisions.

`AGENTS.md` in this directory is generated by `next dev` and points agents at the bundled Next.js docs; keep it committed.
